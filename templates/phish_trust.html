Trust and privacy

Email analysis should be private, explainable, and reversible.

PhishAnalyze helps people inspect suspicious emails inside their own workspace. Uploaded messages are used for the requested analysis, stored only for workspace history, and can be deleted by the user.

Data use

Uploads are for analysis, not model training

Email files are processed to produce the scan result and evidence. They are not added to public demos or training datasets.

Evidence

Each result shows analyzer status

The app shows which checks completed, which checks were unavailable, and which checks require a higher plan before they can run.

Retention

Workspace history can be deleted

Signed-in users can remove stored scan results from their workspace history. Production retention jobs can also purge older records.

Authentication

Owner admin access supports user-bound passkeys

Public users sign in with normal workspace accounts. Only an explicitly allowlisted platform owner/admin can enter private admin routes after a fresh passkey step-up. Tenant owner role alone is not enough. The legacy analyst token remains for internal API compatibility.

Mailboxes

Mailbox Scan now requires explicit connection

PhishAnalyze does not read an inbox just because someone signs in, and it does not poll connected mailboxes automatically. A signed-in user must explicitly start each Scan now request using a connected mailbox, encrypted credentials, and plan permission.

Third parties

Paid API-backed checks are visible

URL reputation, domain intelligence, sandbox, browser, and LLM checks are shown as included or locked so users know what happened.

Operations

Runtime alerts omit mailbox content

Analyzer outages, repeated campaigns, high payment risk, and login throttling can notify operators without email addresses, subjects, URLs, message content, client IPs, or raw workspace identifiers.
